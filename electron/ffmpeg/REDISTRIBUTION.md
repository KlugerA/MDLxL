# FFmpeg 8.1.2 for MDLxL

This application invokes an unmodified FFmpeg executable built by serversideup/ffmpeg-lgpl-builds, release **v8.1.2-27** (14 July 2026). It is LGPL-2.1, with GPL, nonfree, version3 and optional library autodetection disabled. The actual executable configuration was inspected; palettegen, paletteuse, GIF encoding, lossless QOI decoding and RGBA PAM encoding/decoding were exercised. MDLxL has no ShareX code or runtime dependency.

Keep the five DLLs, complete license texts, SOURCE.txt and PROVENANCE.json beside ffmpeg.exe. MDLxL invokes this exact local path without a command shell, PATH lookup or download. No GPU encoder is used for GIFs. The executable can be replaced by the user; the package-build verifier checks the reviewed binary to prevent accidental packaging omissions.

Redistribute **MDLxL-FFmpeg-corresponding-source.zip** together with the portable MDLxL ZIP, and offer it alongside every application download. That companion contains the exact upstream ffmpeg-8.1.2.tar.xz (SHA-256 464beb5e7bf0c311e68b45ae2f04e9cc2af88851abb4082231742a74d97b524c), the pinned builder archive, GCC/MSYS2 source including patches, corresponding mingw-w64 runtime sources, Intel oneVPL 2.17.0, OpenH264 2.6.0, NVIDIA codec headers n11.1.5.3, AMD AMF headers 1.5.0, build recipes and full notices. Its source manifest records archive hashes and exact origins.

The builder archive contains scripts/build-windows.sh and .github/workflows/build.yml. On a Windows MSYS2 MINGW64 build host, install the recorded toolchain/development dependencies, extract the builder, place ffmpeg-8.1.2.tar.xz in its build directory and run `bash scripts/build-windows.sh --target x86_64-pc-windows-msvc`. The script verifies the upstream source hash, configures and builds FFmpeg, then verifies licensing flags and its complete DLL import closure. Source-only restoration can use the supplied archives in place of the script's upstream downloads. No MDLxL patch is applied to FFmpeg. MDLxL's source folder itself needs no Git repository; upstream build scripts are preserved as distributed.

GCC runtime libraries are distributed under GPLv3 with the GCC Runtime Library Exception; both texts are included. This exception and the permissive licenses of oneVPL, OpenH264 and winpthreads are compatible with this LGPL FFmpeg build. AMD/NVIDIA header and mingw-w64 notices accompany the runtime too. The companion includes corresponding source and package recipes instead of relying only on a general upstream source link.

Capture implementation: frames remain full color, losslessly stored as QOI using an original MDLxL encoder. Timestamps are rounded cumulatively to GIF centiseconds. Both FFmpeg passes read one native-controlled concat manifest. The first builds a complete-recording palette (`stats_mode=full`); the second applies `sierra2_4a` for Medium/High or `none` for Low. A PAM palette preserves its alpha entry without needing an optional PNG codec. The final GIF delay and loop mode are explicit.

Temporary storage is capped at 8 GiB, further limited to half of available temporary-volume space after a 512 MiB reserve. Each lossless frame charges its file size plus 512 bytes for timestamp/path/manifest bookkeeping. This replaces the old encoded-byte threshold; there is no recording-duration cap. Capture stops and finalizes accepted frames when that budget is reached. Output retains the 256 MiB GIF size limit. Accepted frames stay on disk with a bounded renderer queue; completed GIFs remain native-owned for Retry Save until successfully copied into Screenshots.
