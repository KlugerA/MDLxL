# Showcase rendering target

Showcase targets classic Warcraft III SD model presentation. It uses the project's WebGL2 `war3-model` renderer with MDLxL's shader adapter for animated normals, geoset tint and alpha, and the existing Warcraft material and texture sampling rules. Recording advances the model in deterministic steps; local and global animation clocks stop when no selected sequence advances.

Portrait sequences use a separate portrait path. The model camera is evaluated at the current frame, the Human UI frame is composed around the render, and the portrait shader uses the classic white directional light with a 0.3 ambient floor. The direction used by this preview is `[0.3, -0.3, 0.25]`, following the coordinate conversion in the [Warsmash portrait light manager](https://github.com/Retera/WarsmashModEngine/blob/main/core/src/com/etheller/warsmash/viewer5/handlers/w3x/W3xScenePortraitLightManager.java) and its [default static light](https://github.com/Retera/WarsmashModEngine/blob/main/core/src/com/etheller/warsmash/viewer5/StaticSceneLightInstance.java). That is a researched reference implementation, not a claim that every Warcraft III patch uses identical portrait data.

The imported renderer documents support for standard geometry and animation, global sequences, layered alpha, texture animation, ParticleEmitter2, and partial RibbonEmitter behavior. It documents no Light-node or render-priority support; RibbonEmitter gravity and texture-slot/color animation are also outside its documented support. Legacy ParticleEmitter and ParticleEmitterPopcorn rendering are not provided by this renderer. MDLxL adds some SD shader behavior, but it does not supply all missing engine features. These limits mean Showcase is not a complete Warcraft III engine replacement. Check effect-heavy or light-dependent models in Warcraft III before treating a capture as an exact in-game result. See the upstream [`war3-model` renderer support list](https://github.com/4eb0da/war3-model/blob/master/README.md#renderer-support).

The quality menu controls preview sampling, antialiasing where the WebGL device supports it, and the maximum capture edge. PNG keeps full color; GIF is limited to 256 colors. Animated GIF backgrounds hold their currently displayed frame during a recording so every exported frame has deterministic background pixels.
